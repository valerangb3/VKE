# Практическое задание 9: асинхронность и корутины

Проект: VKE. Ветка: `hw7`.

Названия из задания адаптированы к существующему проекту:
`AppDetailsViewModel` → `DetailsViewModel`, `AppDetailsState` → `DetailsUiState`,
`AppDetailsScreen` → `DetailsScreen`, `AppApi` → `CatalogApi`.

## 1. Отменяемая установка

В `DetailsUiState.Content` добавлено поле `installState`:

- `NotInstalled` — кнопка «Установить»;
- `Installing(progress)` — кнопка «Отменить», индикатор и процент установки;
- `Installed` — неактивная кнопка «Установлено».

`DetailsViewModel.onInstallClick()` запускает `installJob` через `viewModelScope.launch`.
Состояние `Installing(0)` выставляется сразу, поэтому повторное быстрое нажатие
отменяет установку даже до первого запуска тела корутины. Затем `emulateInstall()`
каждые 150 мс увеличивает прогресс на 5 до 100. Полная эмуляция занимает около 3 секунд.

При отмене вызывается `installJob?.cancel()`, ссылка очищается, состояние сразу
возвращается в `NotInstalled`. `delay()` поддерживает кооперативную отмену и
выбрасывает `CancellationException`: отменённая корутина не продолжает цикл
и не переводит запись в `Installed`. Следующий запуск начинается с 0.

`installJob` — дочерняя корутина `viewModelScope`, поэтому очистка ViewModel
отменяет установку автоматически. Повторная загрузка карточки также отменяет её.
Завершение фоновой загрузки похожих приложений обновляет только `similarApps`
через `_state.update`, сохраняя текущий прогресс установки.

Это эмуляция: APK не загружается и системная установка не запускается.

## 2. Рейтинги каталога

В `CatalogApi` добавлен `suspend fun getRating(id: String): Float`:
он выполняет `delay(1500)` и возвращает `(30..50).random() / 10f`.
Этот метод имеет реализацию по умолчанию и не делает HTTP-запрос.
Отдельный тест проверяет его вызов на настоящем Retrofit-прокси.

В `AppRepositoryImpl` реализованы:

1. `loadRatingsSequentially(ids)` — обычный цикл, следующий запрос начинается
   после завершения предыдущего.
2. `loadRatingsInParallel(ids)` — `async` для каждого id внутри `coroutineScope`,
   затем `awaitAll().toMap()`. Число одновременно запущенных запросов не ограничено.

Рейтинги хранятся в `AppListUiState.Content.ratings` по id и передаются в `AppItem`.
До загрузки карточка показывает «★ —», после — звёздочку и число с одним знаком
после запятой. В каталоге есть две кнопки: «Рейтинги: последовательно» и
«Рейтинги: параллельно». Нажмите их по очереди, чтобы сравнить способы на текущем
каталоге. `AppListViewModel` замеряет каждый вызов через `measureTimeMillis` и
отображает оба результата. Во время загрузки кнопки заблокированы, повторный
вызов из ViewModel также защищён от наложения запросов.

Ошибка рейтингов оставляет список доступным и позволяет повторить загрузку.
`CancellationException` пробрасывается дальше. При повторной загрузке каталога
предыдущая загрузка рейтингов отменяется.

## 3. Замеры на 12 приложениях

Фактический запуск `RatingsBenchmarkTest.compareBothModesOnTwelveAppsWithRealDelays`
выполнен 15 ноября 2026 года на macOS arm64, Gradle 9.4.1, JVM 21.

Использован воспроизводимый тестовый каталог из **12 AppDto** с уникальными id.
Из него реальный `AppRepositoryImpl.getApps()` получает приложения. Затем на
одном и том же списке id сначала вызывается последовательный способ, потом
параллельный. `CatalogApi.getRating` не переопределён: применяется настоящая
реализация с задержкой 1500 мс и случайным рейтингом 3.0–5.0.
Сам HTTP-каталог исключён из замера, чтобы измерять именно получение рейтингов.

| Способ | Измеренное время | Теоретическое время задержек |
| --- | ---: | ---: |
| Последовательно | **18 051 мс** | 12 × 1500 = 18 000 мс |
| Параллельно без ограничений | **1 511 мс** | около 1500 мс |

Параллельный вариант оказался примерно в **11,95 раза быстрее**.
Небольшая разница с теоретическим временем связана с планированием корутин
и накладными расходами выполнения. Оба способа вернули 12 рейтингов в диапазоне
3.0–5.0. Случайные значения при двух вызовах могут различаться.

Замер сделан с `runBlocking` и реальным временем, а не с пропускающим задержки
`runTest`. В автоматических проверках репозитория отдельно используется виртуальное
время: 18 000 мс для последовательного варианта и 1500 мс для параллельного.

Команда воспроизведения реального замера:

```sh
./gradlew :app:testDebugUnitTest --tests 'com.vgb3.vke.data.repository.RatingsBenchmarkTest' --rerun-tasks
```

В стандартном выводе теста сохранена строка:

```text
RATINGS_BENCHMARK apps=12 sequentialMs=18051 parallelMs=1511
```

## 4. Structured concurrency и самопроверка

- `viewModelScope` ограничивает жизненный цикл установки и запросов рейтингов
  жизненным циклом ViewModel.
- `coroutineScope` дожидается всех дочерних `async`. Отмена родителя отменяет
  каждый запрос. Ошибка одного запроса отменяет его соседей и передаётся вызывающей
  корутине. Внешних scope и `GlobalScope` нет.
- Обычный `suspend`-вызов внутри цикла остаётся последовательным. Само наличие
  `suspend` не запускает запросы одновременно.
- `delay` приостанавливает корутину, сохраняя поток свободным для UI и других корутин.
  В рабочих экранах нет `Thread.sleep` и `runBlocking`.
